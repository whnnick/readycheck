# 真实场景验收清单

[English](QA.md) | 中文

发布预览构建或验证用户反馈回归前，使用这份清单。不要把 token、回调 URL、账号 ID 或原始 usage 响应贴到公开 issue。

## 0.1.88 历史通知回归

- 旧版记录应显示“历史送达未验证”及缺少凭证的说明，不能被标记为投递成功或重置读取失败。
- 当前重置到期时间与历史通知分别展示，不以旧通知推断当前可用重置。
- 中英文、摘要和全部通知列表的说明应换行、不遮挡状态。
- 自动化覆盖：本地化完整性、旧历史迁移及 Windows UI smoke。Windows 原生视觉仍需实机验收。

## macOS 安装与更新

1. 在没有运行 ReadyCheck 的 Mac 上安装最新 DMG。
2. 确认 Finder、Dock 和菜单栏中都显示 ReadyCheck 图标。
3. 启动旧版本并执行“检查更新”。确认可以检测到 GitHub latest release，并且下载操作会打开发布页。
4. 断开网络后执行“检查更新”。确认应用显示失败提示，而不是卡住界面。

## macOS Codex OAuth

1. 点击“连接”，在浏览器完成 OAuth 授权。
2. 确认 ReadyCheck 可以自动收到 `localhost:1455` 回调。
3. 如果没有收到回调，粘贴最终回调 URL 到手动输入框并完成授权。
4. 确认已连接账号显示登录邮箱，而不是内部 account ID。
5. 断开账号，确认界面回到未连接状态。

## 安全刷新与准确性

1. 执行手动刷新，确认不会访问模型推理 endpoint。
2. 确认主窗口动态展示 Codex 当前实际返回且可验证的额度窗口，不预设固定的 5 小时/7 天组合。
3. 与测试者可见的 Codex 或 ChatGPT 用量来源对照显示数值。
4. 如果上游响应结构变化，ReadyCheck 必须显示不可用或隐藏百分比，直到 parser 测试更新。
5. 使用过期 token 场景验证，确认刷新 token 成功，或 fail-closed，不猜测百分比。

## Widget 行为

1. 首次启动后，确认“显示 widget”默认开启，并且 widget 完整位于屏幕可见区域内。
2. 隐藏 widget 后，只点击一次“显示 widget”。确认它回到和“重置位置”一致的右下角默认位置。
3. 关闭“置顶 widget”。确认普通应用窗口可以覆盖 widget，且 widget 仍可拖动。
4. 拖动 widget。确认主窗口不会被打开。
5. 单击 widget 内容区域。确认主窗口打开。
6. 在“极简”和“详细”样式之间切换，确认标签不会换成竖排文字。

## 低额度与异常状态

1. 测试或模拟任一额度窗口低于 25% 剩余，确认显示提醒和红色进度条。
2. 断网后刷新，确认应用不会把过期或失败数据变成猜测百分比。
3. 确认过期额度快照会标记为过期或不可用，而不是继续显示为当前可用。
4. 在登录仍有效、仅发生临时断网或服务异常时，确认显示“重新尝试”，且无需重新登录即可恢复。
5. 模拟授权被拒绝或刷新凭据失败，确认显示“重新登录”；替换授权取消或失败时，不应删除此前仍有效的凭据。

## 本地额度消耗

1. 同一账号的官方 app-server Token 用量可用时，确认看板切换为真实 7/30/90 天 Token 数据，并明确标注官方来源。
2. 官方 Token 历史不可用时，完成至少两次间隔超过 1 分钟的成功刷新，确认本地看板显示当前可用额度窗口。
3. 确认本地柱形展示检测到的额度下降百分点，当前剩余额度单独显示。
4. 确认额度重置或恢复不会产生负消耗，长时间刷新断档不会被归入柱形。
5. 切换时间范围不会影响悬浮 widget，也不会触发网络请求。
6. 检查本地历史文件，确认其中不包含邮箱、account id、凭据或原始接口响应。

## 额度与 Credits 通知

1. 主动重置额度将在 72 小时内到期时，确认 ReadyCheck 会在需要时请求通知权限，并发送一次到期提醒。
2. 重置详情不可用或限流时，确认 ReadyCheck 显示“暂时无法读取”而不是 0，并保留上一次仍未过期的已验证结果；只有明确返回 `availableCount: 0` 时才清空。
3. 再次刷新并重启应用，确认同一个过期时间不会重复提醒。
4. 经验证的额度已用尽时，Credits 余额不变不应提醒；余额开始下降后应出现一次 Credits 使用提醒。
5. 同一轮额度耗尽期间，Credits 后续继续下降不应重复提醒。
6. 额度恢复或经过验证的额度重置周期推进后，再次耗尽并发生 Credits 下降时，应允许下一轮提醒一次。
7. 拒绝系统通知权限后，确认额度刷新仍可正常使用，不报错，也不发送模型请求。

## Windows 预览版黑盒验收

1. 在 Windows 10/11 上运行 `apps/windows` 预览版，确认系统托盘图标、托盘菜单、主窗口和桌面 widget 都能显示。
2. 点击“连接”，在浏览器完成 Codex OAuth 授权，确认应用能自动接收 `localhost:1455/auth/callback` 回调。
3. 授权后确认账号区域显示登录邮箱，刷新后动态显示 Codex 返回且可验证的额度窗口。
4. 本机安装 Codex 且登录同一邮箱时，确认显示官方 Token 看板；Codex 不存在或账号不同时，确认只读 OAuth 回退仍能刷新额度。
5. 对照可见的 Codex / ChatGPT 用量来源检查百分比和重置时间；如果明显不一致，记录截图和时间，但不要公开 token、account id 或原始 usage 响应。
6. 断网后刷新，确认 Windows 版不会显示猜测额度；缺少 token、account id、请求失败或 parser 失败时必须显示不可用。
7. 首次启动、隐藏后重新显示、点击“重置位置”三种场景下，widget 都应回到同一个右下角默认位置，并完整位于屏幕内。
8. 关闭“置顶 widget”后，普通应用窗口应能覆盖 widget，widget 仍应可拖动。
9. 切换极简 / 详细 widget，确认文字不竖排、不遮挡、不溢出。
10. 退出应用后重新打开，确认已授权状态可以恢复，token 文件不是可读明文 JSON。
11. 重复上面的通知场景，确认 Windows 系统通知同样遵守“每个过期时间一次、每轮额度耗尽一次”的规则。

## 发布门槛

- `swift test` 必须通过。
- Windows 子项目 `cd apps/windows && npm run check` 必须通过。
- `scripts/package_dmg.sh` 必须生成当前版本 DMG。
- `hdiutil imageinfo dist/ReadyCheck-<version>-macos.dmg` 必须能成功读取 DMG。
- README、更新日志和 release notes 必须使用同一个版本号。

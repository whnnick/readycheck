# 0.5.0 — 提醒更可控，运行更省心

[English](PLAN.md) · [设计预览](prototype/README.zh-CN.md) · [技术调查](TECHNICAL.zh-CN.md) · [黑盒验收](QA.zh-CN.md) · [版本索引](../../VERSIONS.md)

当前0.5.0-dev.3修复成功回执丢失、保持受保护账本打开，并展示卡片观察、请求准备及合并后的失败检查。全量398项与最后定向／原生检查通过；真实读取和历史卡片来源已查看，锁屏期间合成读写和真实应用检查已通过，用户确认解锁后，真实读取、账本及原设置保留已核验。昨夜事件仍未确认，不承诺免确认升级，未公开发布。详见[可靠性验收](QA.zh-CN.md)。

## 目标与范围

1. **P0 升级后连接恢复**：定位反复钥匙串确认的原因，验证同路径升级、冷启动和锁屏恢复。保留系统必要确认。以真实升级恢复证据决定是否可声称改善，不承诺完全免弹窗。
2. **P1 到期提醒节点**：在现有「设置 → 提醒 → 重置卡到期提醒」下直接勾选72／48／24／12小时；不新增主导航页，不加折叠层。
3. **P1 数据状态**：沿用右上角「数据状态」，直接展示当前来源、最后成功、最后尝试、本轮连续有效记录时长／数量和当前不估算的具体原因。

## 提醒行为契约

- 老用户保留原到期提醒开关、已提交／已提醒节点、历史、账号隔离和自动用卡授权；新节点字段缺失时默认四项全选，保持现有提醒行为。自动用卡新用户仍默认关闭，已授权用户保持原状态。
- 开启到期提醒时至少选择一个节点；最后一项不可取消，并说明可使用总开关关闭。总开关关闭后保留节点选择。
- 每张卡、每个节点、同一账号只提醒一次。关闭再开、修改节点、刷新、重启均不清除已处理标记；0.4.1的提交去重与明确失败重试规则保留。
- 错过多个节点时保留现有合并策略：在有效读取时最多发送一个最临近到期的、已选且未处理节点，并处理当前已跨过的节点。不能按选择项循环补发多条。新增选择不重发已处理节点；所有通知仍须通过现有账户／数据有效性检查。
- 节点保存与提醒评估串行化，保存失败恢复上一值并显示行内错误；旧异步读取不能覆盖新选择。下一次有效刷新采用保存成功的规则。
- 到期提醒、自动用卡授权、用卡成功通知三者独立。关闭到期提醒不关闭自动用卡；确认自动用卡成功后仍发送通知。系统通知是否展示仍受系统设置控制。
- 原系统通知入口、测试通知、最近记录、全部记录及记录状态语义全部保留；预览中的示例记录不是新功能。

## 数据状态契约

连接是否正常与估算是否可用分别表达。可正常显示额度但暂不估算，不应提示重新登录。显示数字来自同一账号、同一5小时周期的有效连续后缀；不能用全部历史长度伪装连续时长。

| 状态 | 直接展示 | 用户操作 |
| --- | --- | --- |
| 观察不足 | 已连续观察多久／几个有效记录；至少30分钟和7个记录，还需通过波动检查 | 正常观察；可刷新 |
| 记录中断 | 已知中断原因和恢复后的连续记录；旧历史仍保留 | 正常观察 |
| 刷新失败／缓存 | 最近成功与最近尝试分别显示；缓存不参与估算 | 刷新读数 |
| 凭据受限 | 无法读取已有凭据，不将其等同登录已过期 | 重试读取，系统必要时确认 |
| 消耗波动／无下降 | 有记录但暂不估算的具体原因 | 正常观察 |
| 可估算／已触线／服务限制／其他不可用 | 保留现有状态与准确说明，不被新增界面覆盖 | 按现有恢复路径 |

所有来源和连接模式保持准确：本地Codex、独立OAuth、来源缺失、窗口缺失、官方拒绝使用仍区分。估算的30分钟／7个记录／10分钟间隔和波动规则不变，不显示保证可用时长；进度仅表达观察时长门槛。主窗口、菜单和Widget读取同一原因，不各自计算。

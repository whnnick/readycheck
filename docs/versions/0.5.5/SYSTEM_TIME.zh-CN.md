# 系统相对时间调查

[English](SYSTEM_TIME.md) · [验收](QA.zh-CN.md) · [计划](PLAN.zh-CN.md)

用户发现，新通知已有完整发送时间，但右上角系统相对时间仍可能不显示。上一次截图验收只证明系统时间能够出现，并不证明始终出现。

临时隔离原生诊断程序沿用应用已有通知权限，不初始化账号模型、不访问凭据、不请求兑换卡片。只发出两条明确标注的测试通知：A 为立即投递的 nil 触发器，B 为一秒后单次投递。两者标题／副标题／正文结构一致。macOS 27.0.1 公开通知接口返回的投递日期均有效，分别约在提交后 0.001 秒与 1.002 秒。

用户打开通知中心后，原生截图显示 A、B 都有相对时间，原先的到期提醒也恢复了时间。因此，没有证据把短延时当作修复。重新展开与显示恢复同时发生，间歇性缺少时间标签的确切原因仍未确认。没有修改正式通知触发器、呈现选项、权限或提醒规则。保留应用可控的完整发送时间兜底，不能宣称永久修复 macOS 相对时间渲染。

仅移除两条诊断标识，确认剩余为零，诊断程序已退出并恢复正式安装包的应用注册，原应用持续运行。前后 17 项偏好、授权、尝试账本、提醒规则、账号与认证缓存摘要一致，普通用卡检查正常，没有测试兑换。私有截图和诊断文件不作为公开素材。本次未改正式代码，复用已有 418 项测试结果。

参考：[Apple 通知日期](https://developer.apple.com/documentation/usernotifications/unnotification/date)、[可编辑通知内容](https://developer.apple.com/documentation/usernotifications/unmutablenotificationcontent)。

## 官方文档结论

- [OpenAI App Server](https://learn.chatgpt.com/docs/app-server)：支持版本对应的 JSON Schema、初始化握手、账号与额度事件、多额度桶及实验能力开关。应以实际安装版本校准接口，不把在线文档当作所有旧客户端都支持的契约。
- [Apple 通知撤回](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/removedeliverednotifications(withidentifiers:))：删除异步完成。0.1.97 已有删除回查，本版补真实系统验证，不能把通知中心记录等同于用户看见横幅。
- [Apple SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)：支持登录项注册和注销。0.1.97 已接入，本版排查 notFound 并验收完整登录周期。
- 以上是本次读取到的现行文档，不代表这些接口在过去两天新发布。没有证据支持宣称 macOS 27 新增了自动撤回能力。

## 已有能力与实际差距

已有本机 Codex/OAuth 两种连接、多额度桶解析、事件触发刷新、轮询回退、唤醒刷新、通知撤回回查和历史状态，不重复开发。
源码中事件监听使用首个发现的可执行文件、固定 30 秒重连，初始化收到相同 id 就发送 initialized，未区分错误响应；阻塞读取没有显式握手超时。读取客户端已有多路径与 12 秒超时，应对齐两条路径，而非重写整个客户端。
0.1.97 QA 仍缺持续通知显示与撤回、专注/锁屏/唤醒、登录项启用和 macOS 14 真机证据。

## P0：发布必须完成

### A. 连接自恢复与简明诊断

- 统一读取和监听的可执行文件选择；区分未安装、未登录、握手失败、协议不支持、暂时断网和数据过期。
- 事件握手设置有界超时；错误响应不得进入已初始化状态。进程退出可重连，失败采用有上限退避；停止或切换账号后旧回调无效。
- 保留轮询兜底，合并事件触发的刷新；事件连接在线不等于额度数据新鲜。显示最近成功更新时间与明确重试入口。
- 诊断只包含应用/客户端版本、连接方式、阶段及脱敏错误码；不输出邮箱、账号 ID、token、路径或原始响应。
- 验收：无响应初始化、初始化错误、首个客户端不可用、客户端退出、断网恢复、停止期间重连、账号切换均有确定性测试；恢复后无需重复登录。超时值及退避上限在实现时由测试固定。

### B. 恢复通知真实闭环

- 保留“非零额度恢复也提醒；验证到再次消耗后撤回”的既有行为。
- 用注入快照驱动真实系统通知适配层，标记为测试通知，不修改真实额度或提醒基线；随后补自然恢复/消耗观察。
- 验收持续通知在前后台显示，消耗后目标条目消失；延迟删除、重启、重复刷新、账号切换不误删或重复发。专注/锁屏/唤醒分别记录。
- 自动撤回以成功读取到新消耗数据为触发点，不承诺用户发出请求的瞬间消失。待重试状态必须可见，手动清除不能标记成自动撤回。
- 发布条件：真实 macOS 持续样式下至少完成一次可控恢复→显示→消耗→撤回；自然周期未观察到须明确记录。

### C. 协议兼容回归

- 从目标 Codex 二进制生成 Schema，记录版本；保留 0.1.97 基线 fixture，加当前版本和未知字段/缺失字段 fixture。
- 覆盖多桶、非固定时间窗、限制状态、重置券未知与零；不猜测额度桶对应哪些模型。
- 事件只作刷新信号，获取完整快照后判断提醒；实验性历史读取不可用时，额度读取仍正常。
- 验收：新旧 fixture 均通过；未知/过期数据不触发恢复提醒，不显示为 0 或 100%。

## P1：在 P0 后完成

登录启动：复现已安装预览包的 notFound，检查 bundle、安装路径、注册错误与签名证据后再定根因，不预先归咎自签名。回读系统状态，等待批准时提供系统设置入口；从设置返回刷新状态。真机验证启用、注销再登录、关闭、升级后状态。未通过则标为实验功能，不宣传为可靠可用。

## 实施顺序与范围

先补 A/C 失败测试，再实现修复与诊断；随后做 B 系统验收；最后处理登录项与打包。建议拆为 3 个功能提交及 1 个版本/文档提交。粗估 3–5 个开发日，不含自然额度周期及额外设备等待。
暂不纳入多供应商、模型额度映射猜测、自动兑换重置券、远程连接、UI 大改、Windows 通知扩展。纯规划不升应用版本；实施时同步 0.1.98 元数据和中英文更新日志。

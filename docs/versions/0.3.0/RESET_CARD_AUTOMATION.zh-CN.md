# 临期重置卡自动使用

[English](RESET_CARD_AUTOMATION.md) · [计划](PLAN.zh-CN.md) · [检查](QA.zh-CN.md) · [版本索引](../../VERSIONS.md)

2026-10-20，本地0.3.0-dev.4。R7：在重置卡到期前1小时自动使用，既有到期提醒继续保留；与节奏估算、低额／恢复通知独立。

## 使用入口

设置→提醒→“重置卡到期前1小时自动使用”，默认关闭。开启会显示明确确认：仅授权当前账号，无论当前剩余额度多少；兑换无法撤销，重置哪些符合条件的窗口由服务端决定。关闭可阻止后续请求，不能撤回已发送请求。不购买或花费付费Credits。

应用自己的60秒后台任务在所有产品窗口收起后仍会检查，唤醒时补查。在到期前1小时内的首次成功检查时执行（包含恰好剩1小时，不含已过期）。这不是云端定时器，退出、休眠、断网、凭据失败或客户端不支持时可能错过。设置卡片显示最近结果及时间；原有到期通知不改。

## 执行与保存

使用[官方Codex app-server兑换接口](https://learn.chatgpt.com/docs/app-server#8-earned-rate-limit-resets-chatgpt)。本机CLI0.162.1生成的协议包含指定`creditId`、调用方`idempotencyKey`及四类结果。不猜测写入HTTP接口、不自动点击官方界面。

执行前重新读取账号和卡片：须账号完全匹配，卡片类型为`codexRateLimits`、状态available、ID非空且唯一、到期时间明确且在未来1小时内；只选最早到期的合格卡。发送前保存卡ID、到期时间及UUID；保存失败不兑换。超时等结果未知时，即使重启也只重试原卡和原请求标识，不让服务端任意挑卡。若该待确认卡消失或过期，记录需核对，并在其原到期前暂停使用其他卡。检查串行；关闭会撤销与不可撤回RPC写入同步的授权，预读期间关闭可阻止发送。确认时捕获账号标识，之后切换账号会使该确认失效。

服务端`reset`／`alreadyRedeemed`表示已确认成功，`nothingToReset`／`noCredit`分别记录，不冒充成功。暂无可重置窗口时，后续检查仍沿用该逻辑请求。兑换响应后重新读取额度并刷新应用，不自行拼造重置后的数据。

单独登录复用既有钥匙串／令牌刷新流程，在私有临时Codex目录使用实验性外部令牌登录；ReadyCheck自身仅通过stdin传入令牌，不放argv、不自行写令牌文件；子进程退出后删除该私有临时目录，不替换本机Codex登录／配置。跟随本机模式使用当前Codex账号，发送前再次核对。不新增Hook／notify接入或任务停止／续接。

## 验收边界

调度、进程协议和模型／界面测试只使用模拟账号与卡片，开发验收不消耗真实卡。真实兑换及服务端结果须等用户授权的合格事件后才能确认，不能把协议存在或模拟成功当作该账号真实兑换已通过。客户端不支持／凭据失败会明确显示并停止用卡。Windows只同步版本元数据。


## 独立到期提醒开关（0.3.0-dev.3）

设置→提醒中将两项重置卡控制放在同一卡片，顺序为：

1. **重置卡到期提醒**：默认开启，旧文件没有此字段时沿用原行为；直接列出72／48／24／12小时规则。关闭只停止后续到期通知，卡片有效期、历史及去重记录保留，已送达通知不撤回。重新开启后在下一次有效刷新时按当前最接近且尚未处理的节点提醒，不集中补发错过的节点，也不重发已通知节点。
2. **重置卡到期前1小时自动使用**：仍独立、默认关闭，开启要确认当前账号及不可撤回的用卡授权。关闭到期提醒不会关闭或授权自动用卡。

低额／恢复／Credits提醒不受影响。新偏好保存于既有提醒存储，通过修订号防止旧投递批次覆盖新选择；等待系统通知权限后、发送前再次检查开关，因关闭而取消的未发送事件不记作投递失败。与之前相同，须保持应用运行并允许系统通知。

## 确认用卡成功通知（0.3.0-dev.4）

新的自动用卡请求收到 `reset` 或 `alreadyRedeemed` 后，按账号保存待通知记录，沿用同一持久请求标识。发送“重置卡已自动使用”，注明卡片原到期时间，不展示账号或请求标识。结果未确认、过期、`nothingToReset` 或 `noCredit` 不生成成功通知。旧开发版没有待通知字段的历史回执不补发。

成功通知独立于到期及额度恢复提醒开关，不另加开关；开启自动用卡时检查通知权限。权限拒绝或投递失败时保留待通知记录，并记录失败的通知尝试；应用运行时下次检查重试通知，不因此再兑换重置卡。关闭自动用卡只停止后续兑换请求，不隐藏已确认发生的用卡结果；仍限定对应账号。

通知中心核验及历史保存完成后才确认通知处理完毕。稳定通知标识和已送达历史用于跨检查、重启去重；历史裁剪后仍保留持久处理标记。系统送达和本地确认之间若进程崩溃，无法提供跨系统事务的严格恰好一次保证。通知中心存在不等于用户已看见横幅，仍受系统通知和专注模式影响；应用内状态及通知历史入口保留。

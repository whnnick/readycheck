## 用户问题

剩余比例不能直接回答“按现在的消耗速度，能否撑到重置”。本版用近期本机额度记录，条件性地对照所选提醒线与重置时间。首期只评估 5 小时额度，7 天额度继续独立显示。

| 需求 | 可验证结果 |
| --- | --- |
| R1 趋势估算与实际读数区分 | 主标题明确“可能／预计”，显示所用时段、速度和提醒线。34% 剩余、每小时消耗24个百分点、10%线时，预计1小时到线；距重置2小时，可能提前1小时触线。 |
| R2 重置对照 | 54% 剩余、每小时12个百分点、重置还需2小时，预计重置前剩约30%，说明依赖后续速度不变。 |
| R3 不足时不估算 | 本轮记录不足、重置、过旧、波动大或没有观测到下降时，不给虚假倒计时；不把零消耗说成无限使用。 |
| R4 三个入口一致 | 总览解释依据；Widget保留最近1小时图，仅加简短结论；菜单栏放读数与摘要。三处共用同一份场景及阈值状态。 |
| R5 提醒不混淆 | 5/10/20% 阈值改变估算目标；低额度通知仍在实际跨线时触发，不因预计触线而自动通知。恢复通知仍需确认实际恢复。 |
| R6 既有功能保留 | 不删账户权益、重置次数／明细、Token页、关于及历史；保留原生Widget／刘海行为、钥匙串、登录和用户偏好；展开Widget只为同时完整容纳既有内容和新摘要增加高度。 |

## 预览边界与候选算法

预览使用合成读数，选择只在内存中保留；不调用账号、模型、钥匙串或系统通知。图表单位为额度百分点，Token 不参与时间换算。

用于交互验证的简化计算：同一周期至少7个采样点、覆盖至少30分钟；相邻间隔须不超过10分钟，额度回升不计作消耗。平均速度为观测下降除以有效分钟数；到提醒线时间为“剩余百分比减阈值”除以平均速度。显示时取约5分钟粒度。前后半段速度相差超过3倍且绝对差异明显时，暂停估算。无下降、过旧或本轮不足时也不显示时长。

这些门槛是待评估的产品假设，不是已验证的预测精度或原生技术方案。正式实现还需处理账号／周期归属、乱序与缺失、明确禁止普通使用的状态、重置时间缺失、样本有效覆盖、预测误差及真实数据回放；不能直接把本原型计算搬到生产。

## 实施顺序

1. 已完成原型阶段：中英文原型、七种场景、三入口与阈值交互，浏览器视觉／键盘检查，用户评审。
2. 当前原生阶段：制定数据契约，先实现共享求值器及回归，再增量接入界面；正式发布前完成脱敏回放及误差评估，当前尚未完成。
3. 发布前：真实周期、睡眠／断网、账号切换、多显示器及通知验收；双语版本说明、公共同步及下载核验。

本阶段不发布、不改全局 Codex 配置、不恢复自动停止／续接实验；不声称消除钥匙串系统确认。0.2.2稳定版的设备验收与发布另行收尾。

旧功能保留是发布前置条件：按[65项保留基线](FEATURE_RETENTION.zh-CN.md)逐项确认实现位置、行为与迁移，不能把网页原型省略当作删减授权；不要求用户回忆或发现漏项。

原生实施沿用现有视图、设置与数据模型，增量接入共享估算及摘要。不得以简化网页原型作为完整应用的替代规格；旧功能完整性由开发方负责核对。

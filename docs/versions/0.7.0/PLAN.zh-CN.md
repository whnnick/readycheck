“连接用户自己的服务”指为读取统计数据连接用户账号、统计接口或其明确选择的本机工具记录，不代表取得模型调用权限。凭据只申请实际读取所需的最小权限；不默认要求所有用户提供推理 API Key 或管理员权限。

## 前端：沿用轻量监控结构

侧栏保留“总览、用量、通知记录、设置”，不新增对话、会话列表或模型聊天选择器。

- 总览：服务切换器加简洁服务列表，默认固定当前关注服务。每家显示真实可得的指标、更新时间和异常；按账号隔离，连接问题不污染其他服务。点击服务查看明细，保留原 Codex 完整总览和权益。
- 用量：按服务、账号、时间筛选；服务支持按模型拆分时才展示模型维度。分别展示订阅配额、官方 Token/请求统计、余额和费用。无数据或权限不足有明确说明，不显示假零值。
- 连接设置：厂商、连接来源、可读取字段、统计覆盖范围、凭据状态和最近成功时间。存在多个来源时给推荐路径及适用说明，避免用户猜测。
- 通知：按服务能力支持额度低、余额低或恢复等提醒；新增种类须验证可获得可靠数据。每账号/统计周期去重，不把轮询失败当额度耗尽。
- 菜单栏、Widget、刘海：继续轻量展示用户固定的服务/指标，支持打开对应明细。保留最近一小时图、拖动、固定、隐藏、快捷操作。不同单位不强行共用同一种进度条。

所有数据明确标记官方、工具记录、估算或未提供，并标明覆盖范围和更新时间。Token、请求次数、余额、订阅百分比和费用分别统计；不合成“总剩余额度”，不直接混加不同币种。

## 后端：扩展现有用量适配层

复用现有 QuotaProvider、凭据存储、历史及提醒系统，不新增 InferenceProvider、ConversationStore、聊天数据或推理网关。

每个服务的只读适配器负责：认证与连接检查、拉取真实可得统计、字段与单位映射、来源/时间/覆盖范围标注、错误分类。必要时把周期用量与瞬时余额作为独立数据类型，避免强塞现有额度百分比模型。保留账号/项目/地域等身份，模型厂商与销售渠道可区分。

数据链路：连接配置 → 最小权限凭据 → 只读适配器 → 标准统计快照 → 按账号历史 → 总览/用量/轻量入口 → 提醒。

独立轮询、限流退避、缓存与过旧标记；单家失败不阻塞全局。后台不调用模型产生消耗。官方账单可能延迟，显示统计区间和数据新鲜度。凭据留在系统安全存储，日志不包含凭据、完整账单或私人账号信息。首版本机处理和保存，无需新增 ReadyCheck 云端账号或统计代理服务器。

## 通用与个性化能力

通用：多服务、多账号、统计区间、来源与更新时间、错误恢复、历史、可验证提醒、隐私和账号隔离。

| 服务 | 计划读取 | 个性化边界 |
| --- | --- | --- |
| Codex | 保留额度、重置、Token、权益和重置卡 | 原自动用卡授权、历史及全部轻量入口保留 |
| Claude | 按来源验证订阅额度或组织统计 | 不混合订阅/API，不默认要求管理权限 |
| Gemini | 按来源验证配额和重置 | CLI、应用与 API 平台的账号和配额分开 |
| DeepSeek | 首先验证官方余额及币种/赠送/充值分项 | 不从余额反推 Token/费用，不伪造百分比 |
| Cursor | 套餐用量及账单周期 | 来源授权、账号绑定和会话稳定性待验 |
| 第二批五家 | 详见实施矩阵的每家独立字段和权限 | 不混淆地域、Coding Plan、开放平台及 Key 类型 |

接入分级：A=官方统计接口且账号具备权限；B=用户明确授权且来源可归属的本机工具记录（只覆盖该工具）；C=只有官方控制台入口，应用显示未支持读取。不能把 C 宣传为已支持统计，不能用模型调用测试替代读取验收。

## 分阶段实施

1. **可行性与数据定义**：围绕用户实际使用的服务建立读取路径、权限、字段、单位、周期和覆盖范围矩阵；用真实账号只读验收。不承诺所有主流厂商都有相同统计能力。
2. **双服务最小闭环**：保留 Codex，接入一个经过验证的新增服务；优先验证 DeepSeek 官方余额，Claude/Gemini 的完整用量读取并行调研。完成连接→统计→历史→轻量入口→可靠提醒。只有余额的服务明确标注余额接入。
3. **统一聚合体验**：接入达到统计验收门槛的更多服务，支持切换和筛选；以可用性及用户需求排序，不用厂商数量凑首发。
4. **设计与发布验收**：重做围绕统计总览和服务切换的设计稿；之前对话稿不沿用。逐项保护原65项能力及0.5/0.6增量，验证设置/账号历史/凭据/自动用卡授权保留；异常、离线、周期重置、通知去重和平台范围分别验收。按现有双语发布和下载核验流程收尾，未经授权不发布。

成功标准：用户能迅速回答“哪个服务还有额度/余额、最近用了多少、何时更新/重置、哪些数据缺失”；统计与官方同口径可对账；不把缺失当零、不跨账号混账、不因轮询产生推理费用；现有用户仍能找到和使用旧功能。Windows 与 Mac 各自验收，不拿一端证据代表另一端。

## 1. 产品判断

按服务和账号组织个性化设置，应用设置只保留整款软件共同遵守的偏好。用户不应在同一长页寻找 Codex 自动用卡和 DeepSeek 余额阈值，也不应每次都重新选择刚才正在看的服务。

归属模型为“应用 → 服务 → 连接/账号 → 币种或额度窗口”；界面以“服务设置”和“应用设置”两个入口呈现。当前单连接直接进入设置，不先增加一层账号列表；未来出现多个账号时再显示账号选择。

这里的服务指具体产品与读取来源，例如 Gemini App 与 Gemini CLI 需要分别归属；无需为同一服务里的每个模型复制整套设置。

## 2. 当前问题与证据

- `SettingsView` 的提醒页同时容纳 Codex 额度恢复、低额度、重置卡到期、自动用卡、DeepSeek 余额提醒及系统通知状态。
- 连接页串列 Codex 与 DeepSeek；管理目录的已支持服务都跳到这一个混合页，缺少准确定位。
- 总览会记住 DeepSeek 选择，但 Token 用量页仍只读 Codex；用户可能误以为看到的是当前服务的数据。
- DeepSeek 提醒已按连接标识和币种保存；Codex 并非所有偏好都按账号保存，例如低额度阈值仍是现有共享字段。界面重组不能被误当成隔离存储已完成。
- 新构建读取既有凭据时可能遇到 macOS 钥匙串提示，用户需要提前知道应用为什么请求授权。

## 3. 导航与页面

```text
总览 / 用量
  Codex   DeepSeek          ← 保留小图标与当前选择
  当前服务 · 当前连接标识   [服务设置]
    连接与数据来源
    提醒
    专属能力（该服务支持时显示）

管理连接
  已连接服务 → 对应服务设置
  待接入目录 → 能力说明

通知记录
  按服务/账号筛选 → 记录详情 → 对应提醒设置

应用设置
  通用 / 显示 / 系统通知与诊断
```

总览右上“管理连接”保留，用于新增、查找和管理服务；当前服务标题旁新增“服务设置”，直接定位当前连接。侧栏“设置”更名为“应用设置”，保留原位置及快捷键。服务设置使用同一内容区域承载，保留服务/账号标题和返回原页面的路径，不叠加多层弹窗。

选择服务后，用量页沿用该服务上下文：Codex 显示官方 Token；DeepSeek 显示余额记录，并说明该接入没有 Token/费用统计。指标名称随来源变化，不把未知显示成零。通知默认聚合，用户从具体服务进入时预选该服务，并可明确切回全部。

侧栏当前的“Token 用量”统一为“用量”。当前查看的服务与 Widget/刘海固定展示的服务分别管理；查看 DeepSeek 不自动改变固定的 Codex。第一期不增加“所有服务提醒总开关”，避免与每条规则和系统权限叠加。

## 4. 设置归属

| 设置 | 所属范围 | 页面位置与规则 |
| --- | --- | --- |
| 语言、主题、登录时启动、更新 | 应用/本机 | 应用设置；不随账号切换 |
| Widget、刘海、全屏隐藏、位置、固定、隐藏时长 | 本机显示 | 应用设置；展示对象明确到服务与连接；现有 Codex 能力保留 |
| 刷新间隔 | 应用偏好 + 服务能力约束 | 先保留现有调度；服务页显示实际节奏，DeepSeek 约五分钟；不承诺所有服务均一分钟 |
| macOS 通知授权、测试通知、持续显示状态 | 应用/本机 | 应用设置；服务页只显示状态与跳转入口 |
| 登录、重连、替换 Key、断开、读取范围、最近成功 | 具体连接 | 对应服务的“连接与数据来源” |
| Codex 低额度、恢复、卡片到期规则 | 目标归属为账号及相关窗口 | Codex“提醒”；第一期复用旧存储，标清现有适用范围 |
| Codex 自动用卡 | 既有获授权账号 | Codex“自动用卡”；原授权、检查记录、回执与去重状态完整保留 |
| DeepSeek 余额阈值 | 连接 + 币种 | DeepSeek“提醒”；明确按总余额判断，展示赠送/充值分项作参照 |
| 默认查看服务/账号 | 本机偏好 | 切换器记忆；断开后清晰回退，不替换规则归属 |
| 通知与历史 | 服务 + 来源 + 账号/连接 | 记录页筛选；不因查看其他服务改写归属 |

服务能力决定显示哪些设置。DeepSeek 不出现 Codex 重置卡；只有余额的接入不出现百分比阈值或模型 Token 筛选；待接入服务没有可以保存的假配置。

## 5. 两个当前服务的具体流程

**Codex**：选择 Codex → 服务设置 → 看当前登录、官方数据范围及最近刷新 → 设置额度/恢复提醒或卡片到期规则。自动用卡独立一节，明确当前授权账号与状态，入口旁可查看检查和回执；仅浏览设置不构成新授权。修复凭据后保留原授权并显示后续检查状态。

**DeepSeek**：选择 DeepSeek → 服务设置 → 连接状态、只读余额范围、最近成功与约五分钟刷新说明 → 提醒按币种设置总余额阈值。保存前展示“当 CNY 总余额 ≤ 所设金额时提醒”；赠送和充值余额不自动获得独立提醒。默认关闭，需要用户主动保存并开启。断开与替换 Key 位于连接区，不与提醒保存按钮混在一起。

从服务页发起连接或替换凭据前，先在本地说明钥匙串可能要求 Mac 登录密码、请求方及用途；不在应用内收集 Mac 密码。凭据读取受阻显示“需系统授权”，不直接误报账号已退出。

## 6. 身份、迁移和恢复

设置不能只用服务名、邮箱或用户自填昵称作归属。服务、读取来源及稳定账号标识共同定义范围；服务不返回可信账号标识时，使用本地连接 ID 并标注“此连接”，不声称识别了真实账户。

- 第一期只搬入口和复用控件，维持旧持久化格式；凭据、通知去重状态、历史与 Codex 自动用卡授权不重建、不默认打开、不扩大适用账号。
- 后续多账号阶段单独设计可重入的迁移，保留原始数据及迁移标记，验证失败可回退。能够证明归属才绑定；不明归属历史继续单独保留，不复制到所有账号。
- 共享的旧提醒偏好须说明其范围；不静默把一次选择复制到未来新账号。新账号默认使用安全的关闭状态；自动用卡继续遵循明确的账号授权。
- 同连接重连可恢复原规则；不能证明同一身份的换 Key 建立新连接，不继承旧提醒或历史。DeepSeek 当前的同 Key 保留连接 ID 规则继续保留。
- 断开立即停止该连接后续轮询及提醒，清除对应凭据；历史是否保留单独说明。删除历史必须是另一个明确操作，不能顺带删除。
- 单家故障只影响该连接；缓存保留原读取时间。切换失败不得沿用另一个账号的余额。

## 7. 实施顺序

1. **Codex + DeepSeek 页面整理**：统一当前服务上下文、增加服务设置入口、拆分两家设置、精确跳转、收拢应用设置；复用已验证的连接/提醒/自动用卡组件。
2. **迁移核对**：先核对现有字段真实范围，再逐项处理共享偏好与连接归属。此期不同时加入新服务或重写授权机制。
3. **多账号及更多来源**：实际需要时加入账号选择、连接重命名与逐账号偏好；复用能力驱动的页面骨架，逐家验收来源。

第一期完成不等于多账号已实现。此次仅完成规划，不改运行中的应用、阈值、授权或凭据。

## 8. 黑盒验收门槛

- 两家服务各自从总览到自己的设置不超过两次操作；返回后恢复服务和原页面。
- DeepSeek 页不出现自动用卡，Codex 页不出现余额币种阈值；应用设置不再堆叠各家提醒表单。
- 当前服务的用量与通知入口可明确判断来源；通知详情准确跳回对应连接的规则。
- 升级前后 Codex 低额度阈值、通知节点、自动用卡授权/历史/未确认结果与 DeepSeek 阈值、启用状态、去重状态一致。
- 换账号、换来源、换 Key、断开、重连及异常恢复不串值；无可靠身份时不合并历史。
- macOS 授权被拒绝可恢复，后台不反复弹密码框；拒绝不会退出其他服务。
- 通知规则已保存但系统权限被拒绝时，分别显示“规则已开启”和“系统通知未允许”，不把投递受阻当成保存失败。
- 窄窗口、中英文、深浅色、键盘、读屏及菜单栏/Widget/刘海入口全部复验；系统显示偏好不随账号切换。

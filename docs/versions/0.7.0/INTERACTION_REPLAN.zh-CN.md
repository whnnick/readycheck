# 0.7.0 交互修正规划

[English](INTERACTION_REPLAN.md) · [旧功能清单](RELEASE_AUDIT.zh-CN.md) · [原设置规划](SETTINGS_PLAN.zh-CN.md) · [版本验收](QA.zh-CN.md)

2026-10-31。状态：用户继续指令后，已将独立 [preview.5 原型](prototype/README.zh-CN.md)导航接入原生 dev.14；详见[原生验收](QA.zh-CN.md)，不据此认定发布验收通过。依据用户最新纠正、当前 dev.13 原生界面的七步审计、Product Design 审计流程，以及 Product Manager 的独立评审。本方案取代原设置规划中“移除旧提醒/连接入口、增加隐藏服务设置页”的实施方向。

2026-10-31 后续纠正：原生 dev.15 按用户最新要求改为连接 → 提醒 → 显示 → 通用，并补齐连接/提醒内的平台图标。此前原型的栏目排序由此替代，保留上次选择与既有快捷入口。

## 1. 产品边界

目标：在用户熟悉的 ReadyCheck 上增加平台连接和统计展示。平台扩展不能让已有任务更难完成。

- 保留总览、用量、通知记录、设置四个主导航，以及原有快捷键。
- 恢复设置里的提醒、显示、连接、通用四项。各平台个性化配置放在对应栏目内按平台切换，不串成一张长表。
- 保留现有 Codex 额度、Token、权益、每张重置卡、自动用卡、检查和回执、通知、历史、菜单栏、Widget、刘海及全部现有偏好。不得用折叠、改名或删除入口代替功能保留验收。
- 本轮只处理 Codex、DeepSeek 的可达性和展示；不新增其他平台实际接入、不做聊天、不重写凭据和授权存储。

## 2. 当前审计结论

审计只操作导航、打开空连接表单后取消；未提交凭据、修改提醒或触发用卡。截图在本地保留，包含真实本机读数，默认不进入公开仓库。

| 步骤 | 当前观察 | 结论 |
| --- | --- | --- |
| E01 总览 | DeepSeek 未连接/凭据受阻时，没有 DeepSeek 切换入口 | 严重：用户无法发现已支持平台 |
| E02 应用设置 | 只剩通用、显示，旧连接与提醒入口不见 | 严重：旧操作路径被破坏 |
| E03 管理连接 | 十家目录混合已支持和待接入服务，按钮都叫查看接入 | 严重：日常连接被迫进入发现目录 |
| E04 DeepSeek 说明 | 看完说明还要点打开连接设置 | 多余中间层，没有完成连接任务 |
| E05 DeepSeek 设置 | 无侧栏定位；返回在内容区，名称只有上一页；未连接与钥匙串失败同时出现 | 定位、恢复目标与状态混乱 |
| E06 连接表单 | 再点连接才出现空 Key 表单；输入前仍显示无法保存到钥匙串 | 既有凭据访问故障与本次表单状态混用 |
| E07 取消与返回 | 取消回到服务页，返回上一页回总览而非刚才的目录 | 能返回，但去向需猜测；本次目标为总览 |

有用部分应保留：余额与 Token 区分、总额/赠送/充值分项、已有提醒控件、系统通知状态、旧历史保留。审计未覆盖实际成功连接、全键盘、VoiceOver、亮色或长内容返回滚动行为；不能据截图宣称这些已通过。

## 3. 推荐结构：旧路径保留，新增路径缩短

| 位置 | 内容与行为 |
| --- | --- |
| 总览、用量页 | 保留现有内容；上方放小型 Codex / DeepSeek 选择器，包含真实连接状态 |
| 未连接平台 | 选择平台后显示简洁连接空状态及连接按钮，不造零余额、假图或假额度 |
| 当前平台标题 | 明确平台名和状态；连接/重试为明确动作，提醒设置为快捷入口 |
| 设置 → 连接 | Codex / DeepSeek 平台列表和当前平台连接详情；可直接完成登录/连接 |
| 设置 → 提醒 | 平台选择器；Codex 显示原有规则及自动用卡，DeepSeek 显示余额规则 |
| 设置 → 显示 | 原 Widget、刘海、置顶、临时隐藏、位置及全屏设置，仍属于本机 |
| 设置 → 通用 | 语言、登录时启动、刷新、更新及系统通知；提醒栏目保留原系统通知摘要和跳转 |
| 更多平台 | 可选的十家目标目录；待接入项目明确说明，不阻挡已支持平台的连接 |

常驻两家已支持平台的提案，修正了此前“只显示已连接服务”的限制：代价是多占一个小型平台入口，收益是新用户和凭据受阻用户仍能找到 DeepSeek。未来更多平台默认只进入更多平台目录，避免长排标签。

“服务个性化”与“保留旧入口”并不冲突：提醒/连接栏目按平台组织，同一条规则只有一份真实配置。总览快捷按钮直接定位到设置里的对应平台及栏目，不再创建额外的隐藏服务页。旧用户初次进入设置仍以 Codex 为默认，之后记住最后查看的栏目和平台；快捷入口则明确指定目标。

## 4. 关键任务与返回规则

1. **首次连接 DeepSeek**：总览点 DeepSeek → 点连接 DeepSeek → 直接出现 Key 表单。目录和说明页不在必经路径上。说明合并在表单里，Key 只由用户在应用输入。
2. **旧习惯连接**：设置 → 连接 → DeepSeek → 同一连接表单。Codex 的原登录、取消、回调兜底、更换授权、退出及重试读取全部保留。
3. **修改提醒**：总览点提醒设置 → 设置/提醒/当前平台。旧路径设置 → 提醒仍有效。DeepSeek 不出现 Codex 自动用卡；Codex 不出现余额币种阈值。
4. **返回**：从总览快捷进入时，在滚动区外固定显示“返回 DeepSeek 总览”；从用量进入则写“返回 DeepSeek 用量”。回到原平台、范围、滚动位置。侧栏设置始终选中，栏目和平台清楚可见。
5. **取消表单**：按钮与 Escape 关闭表单，回到打开表单的位置，不清空原连接、不保存半成品、不跳平台。
6. **查看其他平台**：只改变当前浏览内容，不改变 Widget/刘海固定对象、提醒规则、账号授权或历史归属。

不能同时存在“返回服务目录”“返回上一页”“关闭”三种含义交叠的逃生路径。目录是独立可关闭的发现面板；常用连接从总览或设置直达。

## 5. 连接状态与反馈

| 状态 | 用户看到的内容 | 原地可执行动作 |
| --- | --- | --- |
| 从未连接 | 未连接；简述可读取指标 | 连接 DeepSeek / 登录 Codex |
| 已有凭据，访问受阻 | 需要 macOS 授权；说明凭据尚未确认，并非判断已退出 | 重试读取；必要时用户在系统提示授权 |
| 正在验证 | 正在验证余额读取；防重复提交 | 等待或取消，不展示假成功 |
| Key 被服务拒绝 | 验证失败；旧连接如存在继续保留 | 修改输入并重试 |
| 网络失败 | 刷新失败；已有缓存标记为上次成功时间 | 重试刷新，不默认要求重新输入 Key |
| 已连接 | 平台、只读范围、最近成功时间 | 刷新、管理连接、提醒设置 |
| 已开启规则但系统权限关闭 | 规则已开启 + 系统通知未允许，分别说明 | 打开系统通知设置 |
| 断开 | 说明只影响当前平台连接；历史保留规则明确 | 用户确认断开；不顺带删除历史或其他平台凭据 |

上次凭据访问错误不应作为新空表单的“本次保存失败”。新表单未提交前不显示本次验证错误；如果尚有旧连接故障，以独立状态说明并保留重试入口。

## 6. 保留门槛与实施顺序

先按现有 65 项清单给每项填写：旧入口、新入口、行为、偏好/历史/授权、验证证据。未修改路径可引用有效基线及适用限制；入口变化必须实测，不能凭测试总数或源码存在认定保留。

第一步修正原型和导航规格，保持旧版布局密度、图标、控件与内容层级；不同时换视觉风格。第二步只接线入口、平台状态和固定返回栏，复用现有组件与存储。第三步处理凭据受阻的原地重试和表单错误隔离。最后才做真实升级和平台验收。每阶段分别验证，不同时改授权、存储格式或后台用卡机制。

## 7. 评审与黑盒验收任务

| 任务 | 必须满足 |
| --- | --- |
| 新用户找 DeepSeek | 总览可见；最多两次点击到可输入 Key 的表单；不用进入目录 |
| 旧用户找连接/提醒 | 旧四项设置入口全部保留，Codex 原控件可发现且行为相同 |
| 关闭通知权限后开启余额规则 | 明确显示规则状态和权限状态；不能混报保存失败 |
| 凭据访问受阻 | 平台入口不消失；看到需授权，可原地重试；不要求默认重登 |
| 总览/用量进入设置后返回 | 固定返回按钮不随滚动消失；准确恢复来源、平台、范围与位置 |
| 从两处修改同一提醒 | 对应同一连接和规则，读回一致，无重复状态 |
| 切换平台 | 仅浏览上下文改变；自动用卡授权、历史及轻量入口固定对象不变 |
| 升级前后 | 逐项比较旧提醒、阈值、到期节点、授权/未确认回执、DeepSeek 规则/去重、位置与登录启动路径 |
| 键盘和最小窗口 | 740×620 中英文、深浅色、长内容下返回与焦点可达；关闭表单恢复发起控件焦点 |

交付顺序：先评审本规划；再提供只包含上述关键任务的可点击原型；用户确认后再改原生应用。当前 dev.13 的规划与测试不能作为新方案已实现的证据。

## 现有代码与下一个最小切片

已读取确认现有 `QuotaProvider.fetchSnapshot`、`ProviderRegistry`、按服务区分的 `CredentialKey` 及凭据存储。当前快照以额度窗口为主；不能伪造百分比，也不能把 DeepSeek 金额塞进 Codex Credits。

只围绕 DeepSeek，下个实现需要：

1. 用明确币种和十进制金额解析官方余额：总额、赠送、充值；单独保留接口返回的 API 可用标记。缺失或错误字段维持不可用，不混加人民币和美元。
2. 仅向固定官方 HTTPS 主机发只读 GET，支持取消和超时；区分凭据拒绝、限流、离线/网络和解析错误。不用模型请求测试 Key，不静默切到网站会话。
3. 仅增加当前所需的余额表示，和既有快照并存。Codex 额度/用卡行为及序列化默认值兼容；没有余额字段不能导致旧历史失效。
4. 新 Key 归属独立服务和连接身份，不复用 Codex OAuth 项、不送入浏览器原型、不输出 Key 或包含账号/账单的响应正文。
5. 按连接保留余额与原始观察时间；变化叫“余额变化”，不能反推费用。缓存保留时间并明确过旧；余额提醒在发布前单独验收按币种阈值和连接去重。
6. 接入原生连接表单、总览和对应轻量入口；分别验收移除/重连及原功能保留。用户可见原生开发使用独立开发版号和双语日志。

## 开发及发布门槛

先用确定性网络/解析样例验证零余额、多币种、未知字段、错误或负数金额及错误分类；再由用户在原生应用的安全入口输入 Key 后真实读取，不通过聊天发送 Key。本次原型工作没有读取或索取任何新增服务凭据。

一个切片完成，指允许的认证方式→真实只读请求→正确单位和归属→历史及过旧/失败状态→适用提醒都得到验证，不是界面显示绿色或编译通过。批量导入应用会话、扫描浏览器 Cookie、云端服务和推理调用都不是前置条件，也不在本次设计阶段授权中。

Windows 单独实现验收。本阶段不打包、打 tag、部署或公共同步；当前安装版及账号/卡片状态保持原样。

## dev.1 进度记录（历史）

已实现独立的 DeepSeek 官方余额只读客户端，以及本地开发版原生连接、钥匙串保存、总览切换和失败／过期提示。模拟响应和凭据隔离测试已覆盖；尚未使用真实账号验证，余额持久历史、提醒和轻量入口尚未接入。

## dev.2 余额历史

本地保存最近 30 天的余额快照，按连接的随机标识和币种隔离；同一连接每币种至少间隔五分钟记录，历史不含 Key。旧格式 Key 在成功读取后迁移到钥匙串中的带标识格式；同一 Key 重连保留标识，更换 Key 生成新标识，不能推断两把 Key 是否属于同一账户。读写错误不覆盖损坏的历史。提醒、真实账号和完整原生窗口验收仍未完成。

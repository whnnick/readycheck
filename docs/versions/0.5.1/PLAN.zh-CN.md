# 0.5.1 — 精简卡片详情，保留设置直达

[English](PLAN.md) · [黑盒验收](QA.zh-CN.md) · [版本索引](../../VERSIONS.md)

[2026-10-25设计审查](DESIGN_REVIEW.zh-CN.md)：优化建议与功能保留边界，尚未实现改版。

用户最终决定：移除只读卡片详情中重复的设置按钮；保留卡片信息、已记录结果、对应通知／详情及关闭。移除底部分隔线，弹窗高度由530缩至480点。全部规则、开关、授权和历史仍在「设置 → 提醒」。

共享下一步中的规则入口仍有用途，保留dev.1的直接滚动定位及重复请求修复；不改无关导航或设置。复用双语原生详情与保留路由回归，再实点核对真实详情和关闭；不为验收兑换卡。

此前dev.2本地包0.5.1-dev.2，公开／正式安装仍0.5.0。dev.1方案仅详情页底部按钮被本次决定取代；本次不发布推送。

## Dev.3历史记录归类

只把“仅由旧提醒补出的未记录结果”归为历史缺口：仍保留在按账号的历史中，不作为“接下来”的当前异常，也不压住真实请求／通知。详情标题为“历史到期提醒”，标明“历史记录不完整”，一次说清当时结果未知，不混入当前授权状态。可用卡与真实请求／回执行为保持原状；不修改存储历史、账号授权或执行逻辑。本地0.5.1-dev.3，不公开推送发布。

## Dev.4连接入口层级

以“跟随本机 Codex”为主要入口，把单独登录收进“其他连接方式”。保留已存来源：已有单独登录用户无须展开，也能看到当前来源、状态、账号及适用的重试／断开控制；只有主动点击切换按钮才变更来源。明确 Token 统计和自动用卡仍需要可用的本机 Codex 接口。不迁移登录、授权、账号归属或历史。验收双语最小窗口、连接竞态／唤醒回归及真实折叠操作，不切换用户账号。本地0.5.1-dev.4，不推送发布。

## Dev.5短暂用卡检查失败

每次失败仍写入所属账号的检查历史。服务／卡片明细读取失败连续至少3次、持续120秒才告警；间隔超过300秒或时钟倒退另起一段。继续原自动重试；凭据、账本、写入、卡片变化、错过窗口及用卡结果不明仍及时提示。后续成功检查只撤回同账号此前对应的明细读取告警，不删除历史、成功／到期通知或其他账号通知；历史注明后续恢复，不补造兑换回执。

额度新鲜可读时，分别解释卡片检查、卡片明细或受保护历史问题并前往用卡设置；仅额度／连接未确认或实际凭据失败前往连接设置。保留未知结果优先级、成功通知重试、账号来源、用卡授权／执行和提醒偏好。先复现回归，再验通知／模型链路、共享原生界面、全量回归和真实读取／原状态保留。本地0.5.1-dev.5，不推送发布、不为验收用真实卡。

## Dev.6 设计实现

[展示边界与功能保留对应](DESIGN_IMPLEMENTATION.zh-CN.md)。用户只授权设计／体验优化，不许砍功能；保留现有控件、账户字段、记录及浮窗行为。完成前检查原生双语／深浅色最小窗口、当前状态语义及原功能路由；仅本地，不推送发布。

## 0.5.1 发布范围

用户授权打包发布后反馈本机Codex经常缺订阅日期。源码确认本机额度／卡片数据不含该日期，只允许匹配账号的登录资料补充。新增合成回归先复现两条跨账号资料断言，再加严格匹配保护；无有效来源时保持未知，明确说明本机来源限制并保留账单入口。不抓取凭据、不用额度重置时间推算、不把旧日期冒充新确认，不迁移设置／授权／历史。[发布说明](RELEASE_NOTES.zh-CN.md)和[保留审计](RELEASE_AUDIT.zh-CN.md)对应本次正式验收。

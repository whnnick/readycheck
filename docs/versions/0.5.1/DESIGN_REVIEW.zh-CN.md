## 判断

下一轮应围绕“数据可信、下一步明确、随时瞥见”整理界面。保留原生macOS风格、系统字体、品牌标识和额度语义色；先改善状态、信息顺序与操作层级，再统一视觉细节。总览是额度仪表盘，菜单栏是快速查看入口，Widget是持续观察工具，刘海是轻量提示。

## 产品数据与用户任务

- 当前账号和连接来源：沿用本机或单独登录；不自动迁移账号。
- 5小时及7天额度：剩余百分比、当前有效性、报告的重置时间。
- 额度重置时间是报告值，仍需新读数确认实际恢复。
- 本机额度消耗：同账号观察到的下降百分点；回看范围和额度周期是两个维度。
- 官方Token用量：Token数量、UTC每日记录、历史累计和固定周期比较。
- 账户权益：套餐、订阅有效期、Credits、卡片数量与每张卡到期时间。
- 提醒：额度恢复、低额度阈值、72／48／24／12小时卡片到期节点及投递记录。
- 自动用卡：逐账号授权、最后1小时窗口、检查状态、实际请求／回执及成功通知。
- 历史：未确认、失败、已恢复和通知投递分别记录；未知不等于失败或成功。
- 使用习惯：高频瞥见额度，低频调整设置；既需要小浮窗，也需要完整核对入口。

## 优先修改的三件事

### 一、统一当前状态与恢复入口

S01中“本次运行最近成功”仍占显著位置，同时出现“不可用”“最新条件尚未确认”和独立重试按钮，另有顶栏刷新及查看连接。上次成功可以是真实历史，但不能让人误读为当前数据有效。

建议把顶栏压成一行当前状态与更新时间；异常放在实际失败模块内，主行动只保留一个。额度失败以“额度暂未更新 · 上次成功……”配重试；额度正常但卡片失败则明确“卡片检查重试中”，不泛化为登录失效。关键用卡结果不明仍突出，不能被折叠或普通重试覆盖。刷新、查看连接和查看检查保留各自用途，通过对应状态出现。

验收目标：正常、刷新中、缓存、额度失败、卡片明细失败和结果未确认均可快速区分；保留历史读数有效期与实际恢复确认规则，不把未知画成0。

### 二、让总览首屏真正成为摘要

S02与S06中，双额度、下一步、整块账户权益占据较多纵向空间，趋势经常只露出标题或落到下方。源码中额度数字40点、卡片内间距14点、内边距18点；数字本身可读，问题在多个区块同时保持较大体积。无需靠缩小所有文字来提高密度。

建议次序：紧凑状态栏 → 双额度 → 最近事件／待处理 → 重置卡简报与近期趋势 → 可展开的完整权益和记录。保留醒目剩余数，减少说明行与无效空档；卡片数量和最近到期保持首屏可发现。套餐、有效期、Credits、每张卡日期全部保留，一次操作可见完整内容。现有额度周期与回看范围不重置、不混合；宽窗口并排，窄窗口按内容堆叠。

验收目标：900×760及740×620点布局中，正常态不滚动即可找到双额度、下一步与卡片摘要，趋势至少可见标题和首段内容；所有权益与历史有明确入口，无隐藏功能或深层折叠。

### 三、把设置页改为“当前结果＋明确控制”

S04自动用卡已开启，说明仍以“默认关闭”开头。开关是真实状态，文案是初始默认，混在一起增加疑问。较长机制说明与多个通知段落也会稀释当前运行情况。

建议按额度提醒、重置卡提醒、自动用卡、记录组织；自动用卡单独成组，展示“已为当前账号启用／授权待确认”、最近检查和当前等待条件。开关与阈值沿右边缘对齐；长机制说明放入单层“规则与限制”，操作前仍展示授权范围与休眠／退出等关键限制。通知摘要显示最近几条，并保留查看全部。

验收目标：开关、授权、实际检查状态不互相矛盾；关闭提醒不关闭自动用卡，关闭自动用卡不删除记录；旧授权、节点、通知去重与全部控制均保留。

## 视觉方向与保留边界

采用中性深浅背景、系统字体和少量层次；蓝色用于明确交互，绿／橙／红仍表达额度和风险。减少重复包裹的圆角大卡片，保留必要分组和系统控件。主内容以清楚的实色层次为主；现有原生菜单和浮窗的系统材质作为产品既定语言保留，不照搬网页对材质的禁令。仅做操作反馈与窗口过渡，不增加无关入场或持续动效。

以下项目必须在后续设计稿与实施清单中逐项对应：双额度和主显示、权益／有效期／Credits、全部重置卡与到期日、恢复和低额度提醒、4个到期节点、自动用卡授权与成功通知、用卡和通知历史、数据状态及恢复入口、两种连接来源、Widget一小时图／固定／拖动／贴边、刘海物理衔接与点击展开、全屏隐藏、关于和更新说明。整理展示不等于获准删除功能，也不授权修改用卡执行逻辑。

# 0.2.0 跨版本体验与交付检查

[English](UPGRADE_REVIEW.md) · [产品计划](PLAN.zh-CN.md) · [黑盒检查](QA.zh-CN.md) · [版本索引](../../VERSIONS.md)

2026-10-16。范围：从 0.1.145 升级到 0.2.0 的完整使用路径。下表观察栏记录起始版本，不代表问题目前仍未修复。原生改动已推进至 `0.2.0` 发布候选，当前实现、真实开发包证据及设备/发布缺口以[黑盒检查](QA.zh-CN.md)为准。源码观察本身不等于真实账号/设备验收。

## 原有能力保留

0.2.0 重构可以改变功能位置，删除能力需要明确的产品确认。dev.7 漏掉账户详情属于回归，不是有意精简。

| 原有能力 | 0.2.0 位置／保留核对 |
| --- | --- |
| 套餐、订阅有效期及账单兜底 | 总览 → 账户与权益；缺少日期仍保留账单链接，已过去的日期标为历史记录。 |
| 主动重置次数及每次到期时间 | 总览 → 账户与权益；未知与零分开，部分日期缺失仍保留暂不可用行。只展示，不自动使用重置卡。 |
| Credits 余额／无限 | 总览 → 账户与权益；缺失明确标为未提供。 |
| 剩余额度、重置倒计时与具体重置时间 | 总览额度卡；主额度选择继续与桌面入口共用。 |
| 本地额度历史及官方 Token 活动 | 分别保留于总览与 Token 用量，单位和来源边界明确。 |
| 刷新、来源与连接修复 | 页头数据状态／刷新、设置 → 连接；保留原凭据和登录操作。 |
| 提醒配置／历史及通知测试 | 设置 → 提醒；保留既有评估器与到期通知服务。 |
| Widget 固定／显示／位置、最近一小时图、刘海及全屏偏好 | 设置 → 显示与现有桌面操作；真实设备已验及待验范围继续以黑盒检查为准。 |
| 语言、刷新间隔、登录项、更新及关于 | 设置 → 通用与现有应用菜单；已对照侧栏改版前的主窗口源码。 |

本表是源码与位置核对，测试和原生验收另行记录，不代表所有设备／生命周期发布门槛均通过。服务未返回的字段必须保留未知，不能用重置卡到期时间或认证令牌有效期推测订阅有效期。

## 五种桌面形态

同一视觉方向的[五状态效果稿](prototype/public/assets/widget-notch-concept.png)，全部合成数据，仅为设计示意。

| 形态 | 读数与操作 |
| --- | --- |
| 圆球收起 | 双环保留，中心为主窗口名称 5h/7d 与百分比；小尺寸优先数值，品牌放到展开态。两环对应关系稳定、可通过辅助描述读出；选中窗口未知显示“—”。 |
| widget 展开 | 规整小卡片，双额度/重置/数据状态优先。显式固定按钮，管理提醒及打开主窗口；消耗图放在次级信息，避免挤占读数。 |
| 贴边预览 | 保持细窄竖条，采用两根纵向进度条上下排列；短暂停留显示带标签的双额度；点击固定、再次操作和 Esc 的含义有状态说明。保留直接向内拖动。 |
| 刘海收起 | 与物理刘海底边无缝连接为连续黑色轮廓，接缝不得露出桌面背景；紧凑单行主读数与细进度条使用实际刘海几何；不占用摄像头或系统菜单的有效区域。 |
| 刘海展开 | 展开面板与物理刘海以连续黑色区域连接，不留空隙、不用三角指示器；向下展示双额度、重置与刷新状态。仅点击展开，悬停不触发，点外部/Esc 收起；独立于 widget 的悬停预览及显式常驻固定。需要时进入主窗口。 |

交互原则：沿用既有合理悬停防误触，时间参数以真实操作校准，不新增一组用户配置。跨入展开面板不闪退；拖动期间不展开。低额度/恢复可短暂提示一次；窗口展开不是系统通知投递证据。减少动态时采用低运动过渡。刘海若不能稳定避让系统区域，先保留可靠的紧凑入口，展开形态不带阻塞缺陷发布。

## 其他路径与优先级

- P0 首次使用：说明当前连接来源/是否验证、空数据下一步、稍后配置提醒；用户主动操作时再请求相关权限。已连接旧用户直接看到原设置，避免重复登录/完整新手引导。
- P0 退出与断开：区分关闭窗口、隐藏浮窗、退出应用和断开账号；历史保留/删除边界清楚，隐藏后有恢复入口。
- P1 诊断：状态页提供简洁错误类别、来源与成功时间，复制前可预览脱敏信息；不含凭据、私人路径或完整原始响应。
- P1 性能：同一设备对比 0.1.145/0.2.0 的空闲、展开、连续刷新和休眠唤醒；记录 CPU/内存/绘制和监听实例，修复持续动画、重复监听或明显回退。复用刷新去重/失败退避，不扩大后台扫描。
- P1 可维护性：一套读数/状态/格式规则供各入口使用，避免每处重新推断额度。只抽取确实重复的逻辑，保持改动可追溯。
- P2 后续：经采样验证的节奏估算、自适应刷新、更丰富图表；不以它们延误可靠的 0.2.0。

## 实施批次与发布门槛

1. 数据正确性：R1—R4 的回归用例和最小修复，旧记录保全/迁移验证。
2. 原生主窗口：使用已选侧栏结构接入真实服务；核对旧用户偏好与失败反馈。
3. 桌面入口：五状态按形态实现，固定/悬停/拖动各自测试并做真实视觉验收。
4. 完整生命周期：首次连接、升级、权限、睡眠、显示器变化、退出与重开；补齐 R5—R10 的证据。
5. 双语文档/版本、干净产物、签名及两平台发布核验；正式发布需要已完成项和设备缺口可见。有额度误报、跨账号串读、迁移丢失、重复提醒或卡住的浮窗时不得发布。

本轮不重新安装 Hook、不修改 Codex 全局配置，不恢复已清理的外部任务控制实验。自动暂停/续接、自动兑换重置券和付费 API 仍在范围之外。

## 用户结果与范围

让用户打开就知道剩余多少、何时恢复、读数是否可信，并能找到和验证提醒设置。菜单栏与可选浮窗继续作为日常入口。

重构必须保留原有能力与可找到的入口。订阅有效期、主动重置和 Credits 余额放在总览；其他既有功能对应[保留核对表](UPGRADE_REVIEW.zh-CN.md#原有能力保留)。

三处界面只分为两类数据：

| 入口 | 问题与单位 | 来源和覆盖范围 |
| --- | --- | --- |
| Widget → 额度消耗 | 主显示额度最近 1 小时，每柱 5 分钟，单位**百分点**。 | 与总览共用按账号隔离的本机记录及下降规则；小图柱高按图内最大值缩放。 |
| 总览 → 额度消耗 | 同一指标的 24 小时／7 天／30 天记录，每柱分别为 1 小时／6 小时／1 天。80%→70% 记为消耗 **10 个百分点**。 | 与 Widget 同一份记录；重置变化、缺失／无效值、额度回升和超过 10 分钟的间隔不计入。累计值与图表范围一致，跨多轮累计可超过 100 个百分点。 |
| Token 用量 | 每天使用了多少 Token？ | Codex 返回的按日统计，日期桶采用 UTC；未返回 Token 统计时明确显示暂无数据，不用额度图代替。 |

Widget 和总览的时间范围、分组与纵轴缩放不同，应对照同一账号、额度和时段的数值，不能按柱高直接比较。Token 统计的覆盖范围不同，与额度消耗没有固定换算关系；额度变化不能还原缺失的 Token 数量，Token 总数也不能还原缺失的额度读数。

标题分清配额周期和查看范围：Widget 写“5 小时配额 · 最近 1 小时消耗”，总览写“5 小时配额 · 最近 24 小时消耗”并随范围选择更新；另列每柱时长和“百分点”单位。Token 图写“每日 Token 数量”，明确每柱一天及 UTC 日期。这些标签仅调整展示。

| 优先级 | 需求 | 原生发布时的可验证结果 |
| --- | --- | --- |
| P0 | 总览／用量／设置分区 | 常用窗口首屏同时可见 5h、7d、重置时间和刷新状态；导航持续可见。 |
| P0 | 数据状态一致 | 断网保留旧读数及原时间；授权失效显示未知；未知不等于零，旧套餐资料不代表当前额度状态。 |
| P0 | 指定额度与账号归属 | 指定窗口缺失不回退为其他窗口；历史按已验证账号隔离，旧记录备份并保留来源边界。 |
| P0 | 平滑升级 | 保留已有凭据、偏好、提醒关闭状态和位置；迁移原子可恢复，升级中断及回到旧版有检查。 |
| P0 | 集中提醒 | 沿用现有提醒引擎，补齐 5%／10%／20% 和关闭；同账号、窗口和周期去重，重启后不重复。恢复需要实际读数证据。 |
| P0 | 可检查的通知状态 | 真实回读权限并提供测试入口；系统条目与横幅观察分别记录，不把系统接受等同用户看见。 |
| P1 | 浮窗可理解、可控制 | 样式参考使用真实组件；主显示名称、读数及状态对应；固定保持展开与置顶分别表达，隐藏后可恢复。 |
| P1 | 主动修复连接 | 后台无交互读取策略回归通过，用户主动修复时才进入相应授权流程；保留升级前凭据。 |

主窗口采用用户选择的[第一版视觉方向](assets/overview-concept.png)：固定侧栏、双额度并列、消耗图和就近提醒入口。去掉重复百分比，使用现有正式品牌素材与原生字体。查看额度的百分点与 Token 历史使用独立单位。

## 已完成的设计交付

本地 React/Vite 原型 `0.2.0-preview.3` 实现三页导航、设置分类、阈值/恢复开关、模拟权限与测试提示、7/30/90 天切换、图表键盘读数、模拟刷新和七种数据场景。浮窗读数与固定/取消固定、隐藏/恢复在网页内演示；窗口层级和全屏设置只展示配置状态。设置→显示新增五形态效果稿入口；刘海展开和新圆球外观仍是设计稿。

示例全部合成，时间锚点为 2026-10-15。网页不连接账号、不访问钥匙串、不发送系统通知、不控制 Codex，也不修改安装版设置。原生样式参考来自 0.1.145 的合成演示组件。页面选择在本次会话内保留，刷新网页重置。

## 实施与交付顺序

1. 交互稿审阅并收敛细节。
2. 沿用现有 SwiftUI/AppKit 结构接入主窗口分区；先补关键状态和行为测试，再调整视图。
3. 接入既有额度/通知服务，验证权限、去重、恢复、凭据与异常处理。
4. 原生黑盒验收：直接向内拖动、固定/取消固定、键盘、辅助技术、重启、睡眠唤醒、多屏与显示比例；逐项记录设备缺口。
5. 双语版本号、更新日志和验收文档一致后，按既有流程打包；用户授权发布时验证公开源码、Release、latest 和下载哈希。Windows 单独列功能对应与待验收项，不从网页原型推断原生支持。

## 后续候选 0.3.0

可靠采样后再做剩余额度趋势、近期消耗摘要、经验证的用量节奏提示和自适应刷新。缺失/重置不当成正常消耗；样本不足不预测，估算不承诺具体任务耗时。CodexBar 的[用量节奏](https://github.com/steipete/CodexBar/blob/main/docs/ui.md#pace-tracking)、[刷新策略](https://github.com/steipete/CodexBar/blob/main/docs/refresh-loop.md)和[钥匙串交互](https://github.com/steipete/CodexBar/blob/main/docs/keychain-prompts.md)作为设计参考，未复制其代码。

本版不承诺自动停止/恢复 Codex 任务，不扩展大量服务商、不自动使用重置券、不新增付费 API。验收以用户完成查看/配置/修复流程为依据，不新增遥测。

原生侧栏已推进至`0.2.0-dev.2`，源码测试及合成原生渲染证据见黑盒检查；桌面形态升级及安装包验收待完成。

菜单栏、保留最近一小时图表的展开widget和刘海详情已进入`0.2.0-dev.3`。源码/测试窗口证据与安装包及硬件验收分开记录于黑盒检查。

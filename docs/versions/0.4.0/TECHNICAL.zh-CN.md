# 0.4.0 原生开发契约

[English](TECHNICAL.md) · [计划](PLAN.zh-CN.md) · [验收](QA.zh-CN.md)

2026-10-21。用户已授权继续原生开发，并在完成后打包、推送。0.4.0-dev.1里程碑后进入0.4.0候选版；发布以实际验收为条件。

- Core纯函数生成最多两条摘要，异常优先，其次临期卡及5h重置；总览、菜单栏、Widget同源。远期卡保留在权益区，计时到点不能推定额度恢复。
- 既有额度明细增加可选卡片来源标记，旧数据继续可读。沿用15分钟补充读取周期，保留实际读取时间；完整字段和新鲜额度读数同时有效才显示条件窗口，拒绝过期或未来时间。保留的部分旧明细仍显示，但不能承诺尝试窗口；不迁移偏好或历史文件。
- 通过actor只读投影现有按账号用卡记录，不创建第二账本、请求、凭据或用卡入口。通知按原请求标识精确关联，旧记录缺失过程不补造。
- 到期行、摘要及历史可点开详情；规则与原有授权保留在设置。未知结果不提供另一张卡重试；换号清除选择及记录，忽略旧账号迟到结果。
- 保护65项基线，定向复验权益次数逐卡日期、主显示、Widget一小时图、固定、菜单快捷入口、独立提醒和关于；未修改路径可复用对应证据，缺少设备条件仍单列限制。
- 验证Core行为、旧文件字节、应用关联及路由、双语最小窗口原生渲染和真实不消耗交互后，再走现有公共同步、打包签名和下载核验。验收不用真实卡，不恢复任务控制Hook，不重复社交视频。

[功能保留审计](RELEASE_AUDIT.zh-CN.md)。

用卡账本受系统保护或不可读取时，必须显示存储异常、授权未确认，不能误报授权已关闭；暂停使用且不允许在账本不可读时重新开启。保留原文件保护和授权，解锁后通过原每分钟检查重新读取，不自动重写或降低文件保护。

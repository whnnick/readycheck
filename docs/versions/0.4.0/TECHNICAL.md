[中文](TECHNICAL.zh-CN.md) · [Plan](PLAN.md) · [Checks](QA.md)

2026-10-21. The user approved native continuation and packaging/push after development. Candidate0.4.0 follows the0.4.0-dev.1 milestone. Publication remains conditional on actual checks, not an empty version bump.

- Pure Core next-event evaluation, maximum two events; issue first, then imminent card and5h reset. Shared by Overview/menu/Widget. Far-future cards remain in benefits. Clock expiry never confirms quota recovery.
- Add optional card-detail provenance to the existing snapshot details. Old decodes stay valid. Preserve the actual detail-read time across the existing15-minute supplemental cycle; require complete fields and fresh quota readings, rejecting expired/future times. Preserved partial details remain visible but unverified for attempt-window claims; no preference/history file migration.
- Expose existing account-owned redemption attempts through a read-only actor API. No new ledger, request, credential or card consumption path. Notification association uses the exact original request ID; missing old process fields remain unrecorded.
- Details open from expiration rows, next events or history. Rules remain in Settings with existing consent. Unknown outcomes never offer another-card retry. Clear selection/records on account change and reject late account results.
- Preserve all65 baseline capabilities. Specifically recheck benefits/counts/individual dates, selected primary, last-hour Widget chart, pinning, menu shortcuts, independent reminders and About. Unchanged-path evidence may be reused; unsupported physical environments remain explicitly scoped.
- Validate Core behavior and old bytes, app association/routing, bilingual minimum-width native render and real non-consuming UI. Only afterward run existing public-sync/package/signature/download verification. No real card spent for acceptance, no task-control Hooks, no social/video republication.

[Retention audit](RELEASE_AUDIT.md).

A protected/unreadable redemption ledger must produce an unconfirmed storage state, not disabled consent. Suspend use, disable re-enabling while the ledger cannot be read, retain the original file protection and authorization, and re-read through the existing minute check after unlock. No automatic rewrite or weakened file protection.

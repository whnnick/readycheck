## 0.7.3 正式版

- 正式版沿用 dev.1 已验收的启动修复，涉及 macOS 应用启动、服务切换图标和 Muse 读取脚本。保存的连接和偏好沿用原有格式。Windows 应用逻辑沿用 0.7.2。

- 公开源码的 macOS 全量测试共 557 项，包含 3 项可选原生取证跳过，失败 0 项。14 项 Muse 脚本检查全数通过。
- 签名 DMG 通过磁盘映像完整性、严格签名、版本、私人路径及资源源码比对。移走构建目录后，已安装的 0.7.3 从「应用程序」两次打开，均读到 Muse 真实额度。没有新增正式版崩溃报告。
- 钥匙串确认后，安装版显示 Codex 5 小时和 7 天真实配额及 DeepSeek 真实余额，两项手动刷新均成功。Muse 在后台定时刷新后更新了最近读取时间，未手动刷新或重新登录。胶囊按原顺序显示三项服务，保存位置与前版一致。
- 本地 Windows 包通过 Node 24 服务和界面检查、ZIP CRC、版本及全部 16 项网页源码比对。GitHub 发布工作流另在 Windows 上执行 Electron 网络和代理检查，通过后上传安装包。原报告 OAuth 403 的设备仍待复测。

## 0.7.3-dev.1 macOS 启动修复

- macOS 27.2.1 上，安装版 0.7.2 渲染服务图标时反复崩溃在 SwiftPM 生成的资源查找函数。资源实际位于 `Contents/Resources`，原函数查找的是 App 根目录和已经不存在的打包构建目录。
- 安装版从 `Contents/Resources` 查找图标和 Muse 脚本。资源缺失时返回空值，由对应功能处理。
- 12 项 Swift 专项检查通过，覆盖安装包目录布局、缺失资源、图标载入和 Muse 集成。14 项 JavaScript 读取脚本检查通过。
- 签名 DMG 通过完整性、内置脚本、版本和私人路径检查。移走打包构建目录后，安装版两次正常启动，Muse 两次都显示真实额度。未发现 dev.1 新崩溃报告，胶囊右边界和垂直中心保持原位置。
- 确认 macOS 钥匙串授权后，安装版显示 Codex 5 小时和 7 天的真实配额，以及 DeepSeek 的真实余额、赠送和充值分项。两项手动刷新成功，Muse 继续显示周额度。验收期间无新增崩溃报告。

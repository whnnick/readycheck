Notification-icon blocker closed for this Mac on October 10: the user reported that the artwork was correct after restarting the computer with local 0.1.134 installed. Earlier 16:56 and 23:44 tests established delivery, not visual correctness. The post-restart result is user-confirmed; there is no automated screenshot or isolated proof of which preceding maintenance step was necessary. Restarting alone is not established as a universal fix. Local signature, account, permissions and notification delivery were verified before the restart. No claim that the system’s historical notifications have been deleted or redrawn.

Validation commands: `scripts/check_release_consistency.sh`, `bash -n scripts/package_app.sh`, `swift test --build-system native --scratch-path <temporary-build-directory>`, the existing DMG packaging entry point with isolated build/dist directories, read-only mount inspection and `codesign --verify --deep --strict`. The native backend avoids the Xcode build directory’s extended-attribute signing failure and preserves the CLI executable path expected by packaging.

A one-time local maintenance step initially re-registered the installed ReadyCheck and restarted only Notification Center; the user's screenshot showed this was insufficient. Launch Services then listed 32 ReadyCheck registrations, including an old 0.1.89 backup. Obsolete ReadyCheck registrations were unregistered without deleting their files, leaving the canonical installed app registered. The old backup was relocated out of Applications and retained for rollback. The current user's iconservicesagent, usernoted, usernotificationsd and Notification Center processes were refreshed. New tests were delivered, but system logs recorded display-sharing suppression of banners; the user inspected Notification Center and confirmed the old gauge remained. The system-level iconservicesd could not be refreshed without administrator authentication. No notification database, permission or reminder history was cleared.

Additional rendering check: the public NSWorkspace icon for the installed bundle was rasterized at 16, 32, 64, 128 and 256 pixels; visual inspection at 32, 64 and 128 pixels showed C. This is evidence about the system file icon, not the notification renderer. The legacy backup archive and its hash manifest stay in ignored local build storage and are not release assets.

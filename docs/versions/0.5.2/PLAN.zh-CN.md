# 0.5.2 — 只保留一个 ReadyCheck 登录入口

[English](PLAN.md) · [验收](QA.zh-CN.md) · [版本索引](../../VERSIONS.md)

已发布版本：`0.5.2`（开发验收：`0.5.2-dev.2`）。用户已明确授权移除本机账号登录选项和刚加入的订阅缓存补丁。ReadyCheck 只使用 OAuth 登录；应用代码不再保留账号来源选择、本机认证回退或直接读取订阅缓存的代码。旧来源偏好不再参与路由，保留原字节用于回滚。

额度与账户权益来自 ReadyCheck 登录账号。后台 Codex 适配器保留同账号 Token 统计、额外命名额度窗口、额度事件和隔离的 OAuth 授权用卡。当 ReadyCheck 凭据缺失、不可读或被拒绝时，本机 Codex 登录不能顶替主额度；其他本机账号的数据不能覆盖 OAuth 额度或提供 Token 统计。

首次加载保留原账号上下文，以读取历史和原用卡授权。尚未确认 OAuth 时，原授权显示为等待确认，不能显示成已关闭或开始执行。同账号登录后沿用原授权；不同账号不会继承。明确退出登录会清除当前账号上下文，受保护的历史授权保留。新鲜 OAuth 额度可以恢复连接状态，缓存和迟到的旧凭据结果不能误恢复。启动先完成首轮凭据与刷新尝试，再安排自动用卡检查，避免读取期间误发暂停通知。

其余额度、Token、提醒、重置卡、Widget、菜单栏、刘海和关于功能保留。本次获准删除的是另一种登录入口，不是上述能力。不删除凭据、不改写历史归属、不放宽钥匙串权限、不为验收兑换真实卡。验证迁移和竞态、双语原生界面、全量回归、签名安装及真实账号。用户现已明确授权打包推送，按对应发布审计收尾；Windows 界面不变，仅同步元数据。

## 订阅日期

已安装 CLI 和桌面协议的 `account/read` 没有订阅日期字段。从配置的 `CODEX_HOME/auth.json`（否则默认 Codex 目录）只读补充显示信息。缓存账号、ID token 内账号必须与当前本机接口账号完全一致；必须有不晚于当前时间的签发时间，以及有效的订阅日期字段。文件最多读取 1 MiB；缺失、受保护、损坏或账号不符时不补充。不探查其他钥匙串、不复制或刷新令牌、不写 Codex 文件。

它属于已保存的登录记录，ID token 过期后也只能作为有日期的历史来源展示，不能用于认证、兑换资格、用卡或实时有效期承诺。界面显示原始签发时间和账单入口，已经过去的日期明确标为“上次订阅日期”。原有有效且账号匹配的单独登录信息仍然优先。单独登录保留；过期或损坏的单独登录凭据不能挡住可用的本机额度。

## 连接与自动用卡

所选来源返回成功、非缓存、未过期且账号明确的额度后，同步恢复连接状态；不能替用户完成正在进行的登录。新成功会使迟到的旧连接读取结果失效。保留原有换号隔离及按账号保存的授权。

本机连接读取失败归为可重试的服务检查，不一律当成凭据错误。真正的凭据访问失败仍及时提醒。只有同账号的卡片检查成功后才解除旧凭据警告，保留诊断历史和未确认兑换结果的警告。后台间隔、用卡条件和兑换保护不变。

## 验证与边界

先复现回归用例，再验证双语原生布局、Swift 全量测试和已签名本地应用。核对真实额度、带来源的订阅日期及普通后台卡片检查，不兑换真实卡。保留 65 项功能基线；本次为增量验证，不声称重新完成全部设备实测。
